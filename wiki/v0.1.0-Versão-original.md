# v0.1.0 — Versão original

> Release: [v0.1.0](https://github.com/00MOREIRA00/docker-postgresql-pgadmin/releases/tag/v0.1.0) · Commit `f37af1c` · 30/03/2024

Primeira versão do projeto, preservada como release antes da reformulação.

## O que tinha

- `docker-compose.yml` com dois serviços:
  - `teste-postgres-compose`: imagem `postgres`, porta `5432`
  - `teste-pgadmin-compose`: imagem `dpage/pgadmin4:latest`, porta `16543`
- Rede `bridge` dedicada entre os containers
- `README.md` com o passo a passo para subir o ambiente e conectar o pgAdmin ao banco

## Como era o compose

O exemplo abaixo substitui as credenciais originais por variáveis de ambiente.

```yaml
version: '3'

services:
  teste-postgres-compose:
    image: postgres
    environment:
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:?defina POSTGRES_PASSWORD no arquivo .env}
    ports:
      - "5432:5432"
    volumes:
      - /home/rneto/Desenvolvimento/Docker-Compose/PostgreSQL:/var/lib/postgresql/data
    networks:
      - postgres-compose-network

  teste-pgadmin-compose:
    image: dpage/pgadmin4:latest
    environment:
      PGADMIN_DEFAULT_EMAIL: ${PGADMIN_EMAIL:?defina PGADMIN_EMAIL no arquivo .env}
      PGADMIN_DEFAULT_PASSWORD: ${PGADMIN_PASSWORD:?defina PGADMIN_PASSWORD no arquivo .env}
    ports:
      - "16543:80"
    depends_on:
      - teste-postgres-compose
    networks:
      - postgres-compose-network

networks:
  postgres-compose-network:
    driver: bridge
```

## Limitações conhecidas

Essas limitações foram corrigidas na [[v0.2.0|v0.2.0-Correções-da-base]]:

- O README mandava conectar no host `postgres`, mas o serviço se chamava `teste-postgres-compose`
- O volume apontava para uma pasta da máquina do autor
- As imagens não tinham versão fixa
- As senhas ficavam escritas no compose
